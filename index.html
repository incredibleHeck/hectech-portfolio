BaseCamp Diagnostics

Pilot

AI-assisted learning-gap diagnostics for classrooms with unreliable connectivity

A teacher photographs a pupil's worksheet, dictates an observation, or types a rubric entry. Gemini multimodal analysis reads the handwritten work and the audio reasoning, identifies the specific misconception behind a wrong answer rather than just marking it wrong, and returns a diagnostic report with a targeted lesson plan and a parent SMS draft.

The hard constraint is that the classrooms it was designed for do not have reliable internet. Offline is the default path, not a fallback. Assessments and voice clips are written to IndexedDB queues and reconciled by dedicated sync managers when an uplink returns, so a connection dropping mid-upload loses nothing and the teacher is never blocked waiting on a network.

Access is scoped by organizationId and schoolId across six roles — teacher, headteacher, org admin, SEN coordinator, school admin and super admin — so a school network sees its own branches and nothing else. Campus Gap Analysis aggregates learning-gap prevalence across branches for network leadership, and an SEN inbox routes screening alerts raised automatically during analysis to the coordinator responsible for them.

Composite Firestore indexes are version-controlled and deployed from the repository rather than clicked together in the console, so the index definitions survive an environment rebuild. Pupil "show your work" uploads are handled out of band by a Cloud Storage trigger, and media handling is tuned for the low-specification tablets these classrooms actually have, so adopting it costs a school nothing in new hardware.

SAIS Portal

Live

Production school information system, grading engine and report-card pipeline

Running in production at sais-portal.web.app. Teachers enter marks, leadership runs the school, and parents receive report cards — the whole chain, with the grading mathematics treated as a specification rather than an implementation detail.

The grading grid had to stop losing keystrokes. The master sheet replaced linear array scans with an O(1) hash-map lookup, isolated every cell behind React.memo with local state buffering, and added focus tracking so a background context sync can never overwrite the cell a teacher is currently typing in. Unmount flush handlers catch the last edit when someone navigates away fast.

Averages divide by subjects actually assessed

A pupil who transferred mid-year is not penalised for marks that were never taken. Two-decimal precision and deterministic competition ranking (1st, 2nd, 2nd, 4th) are enforced identically across analytics and printed reports.

Verified in source · grading engine

Authorisation lives on the server. Term locks are enforced in Firestore security rules as well as in the client, and the signed-in role is resolved from a server-side whitelist collection — never from localStorage, which any user can edit. The client check is a convenience; the rules are the boundary.

Five academic years were ingested from historical CSVs with alumni auto-registration and archived behind read-only role locks with an explicit headteacher override. A three-way inconsistency in how years were stored got unified into one canonical YYYY-YYYY form with a documented invariant, because comparing two year strings raw had been a recurring source of bugs.

Bulk PDF generation explicitly releases canvas GPU memory and unmounts React roots in a finally block, then packages a whole class into a single ZIP with browser yielding — which avoids both the memory leak and the multi-download popup block. Parent delivery over the WhatsApp Cloud API records what actually happened via webhook rather than trusting a 200 response, and inbound replies are stored for a human to read. A "STOP" is never acted on automatically, because withholding a child's report card would be the wrong outcome.

EduScheduler Pro

v1.0.0

Multi-constraint timetable, exam and duty-roster generator sold as a one-time purchase

Academic timetabling is a constraint satisfaction problem over teachers, rooms, class groups and curriculum splits. The solver is a hybrid: dynamic minimum-remaining-values ordering with backtracking, so it always assigns the most constrained slot next and unwinds cleanly when a branch dead-ends. It runs inside a Web Worker, so the interface stays responsive while it searches. When it cannot place something it reports the unplaced lesson and the curriculum gap explicitly, rather than silently dropping them and producing a timetable that looks complete.

Divisions were the hard part. Schools that run more than one bell schedule — a nursery section and a senior section on different day structures — break any scheduler that compares period indices, because period 3 is not the same hour in both. Conflict detection was rebuilt to compare real clock times, and that change had to propagate through the generator, the exam rosters and duty assignment alike.

14 classes · 39 teachers · 615 periods · 0 unplaced · under 3 minutes

Measured on the Dansoman campus export: 39 of the school’s 55 teachers, because the nursery department’s timetable was already fixed and was excluded from the run. No unplaced lessons, no curriculum gaps, no hard conflicts, and the whole timetable solved in roughly 270 seconds. The fixture is kept out of version control because it contains real staff data, which means CI cannot run this gate — so it is documented as a manual step before any release.

EduScheduler v1.0.0 · measured run on a real school export

Multiple weeks of manual work became under three minutes of search — and it removed the residual room and staff clashes that had survived the manual process anyway. That ratio, not the raw speed, is the argument for solving this as a constraint problem.

Offline licensing with real cryptography. Activation verifies an Ed25519-signed licence key against a public key embedded in the binary, with a keypair-generation and key-minting toolchain behind it. No account, no server call, and a tampered key is refused. The trade-off is that if the embedded key and the signing key ever disagree, every key issued is rejected and there is no update channel to correct it — so that check is on the pre-delivery list.

Automatic restore points with undo/redo mean a destructive edit is recoverable without anyone having remembered to export a backup — and the restore is itself undoable, because the pre-restore state is captured first. Diagnostic tooling ships alongside: smoke tests, benchmarks, an unplaced-lesson explainer, clock-overlap detection and room-utilisation analysis. Exported problem reports carry counts only — no staff, class, room or school names — so a school can send one without sending its data.

Nexus Inventory

Delivered

Stock ledger, point of sale and direct thermal-receipt printing, built natively in Rust

Thermal printing with no vendor driver. ESC/POS command bytes are assembled in Rust and sent two ways: over raw TCP to a network printer on port 9100 with a connect timeout, and over USB bulk transfer via nusb, with device enumeration and endpoint discovery done by hand. No print spooler, no third-party SDK, no driver install on the shop's machine.

Underneath is a native Rust IPC data layer over rusqlite in WAL journal mode, with foreign keys enforced and a busy timeout set, carried through seven versioned schema migrations. Each migration is gated on PRAGMA user_version and wrapped in a transaction that rolls back on failure, ending at a sync_queue with retry accounting built for cloud replication.

The SQL bridge is allow-listed

Queries crossing the IPC boundary are validated before execution. DROP is permitted only for the views that migrations legitimately recreate, and PRAGMA is restricted to four known-safe pragmas. Anything else is refused rather than passed through to SQLite.

src-tauri/src/lib.rs · read in source

Local backups are encrypted with AES-256-GCM using a per-backup random salt for key derivation and a fresh 12-byte nonce, with both prefixed to the ciphertext so a backup file is self-describing. PIN-based authentication with role-based access control covers the shop floor, and the purchase-order flow composes an order message for WhatsApp rather than embedding a fragile integration that would break the first time Meta changed something.

Built on Tauri rather than Electron so the app uses the system webview instead of bundling a Chromium runtime — a deliberate trade of ecosystem convenience for install size and memory headroom on the low-spec Windows machines this has to run on.

Victor — Ghanaian Damii Draughts Engine

Jan 2027

A full engine, training pipeline and client for a 10×10 variant that had no engine

The rules are the specification, and the tests pin them. Ghanaian Damii differs from international draughts in ways that change the search itself: mandatory capture but free choice — the maximum-capture rule is disabled, so a player may take any available path regardless of how many pieces it wins. Men capture backwards. Kings fly. There is no mid-capture promotion. And a player loses immediately when their piece count drops below two, which cuts off long king chases. Each of the seven rules is named by the test that enforces it.

The board is horizontally mirrored relative to FMJD notation. I documented why that is a display convention rather than a symmetry: a true horizontal reflection flips square parity and maps dark squares onto light ones, so the board's real symmetry is a 180° rotation with colour swap. The mirror helper is marked display-only and must never be used for data augmentation — doing so would have silently poisoned the training set with illegal positions.

NNUE evaluation, trained end to end. Self-play data generation writes a dense 40-byte packed record per position, grouped by game id so splits happen per game rather than per position — consecutive plies of one game are near-duplicates, and splitting naively would leak across train and validation. Weights quantise to int16 with quantisation-aware clamping during training, and every weight file carries a version header so an architecture mismatch is rejected rather than silently misread.

A published Elo claim, withdrawn in the repository

I had reported the network as roughly 100 Elo weaker than the hand-crafted evaluator. On re-examination the benchmark had been measuring the hand-crafted evaluator against itself, because the engine silently fell back when no trained weights were present. The figure is retracted in the README, the fallback path is now unreachable from a search, and the benchmark exits rather than reporting a comparison it cannot make. Perft baselines are likewise labelled as not externally validated.

README.md & ARCHITECTURE.md · in repo

A ≤5-piece endgame tablebase solved by retrograde analysis covers the 2v2 and 3v2 tiers — 18 million positions in the 2v2 tier alone. Under the death check a side below two pieces has already lost, so 2v2 is the smallest tier that means anything. The WASM bundle is size-tuned separately from the native profile at 337 KB, and runs in a Web Worker so browser play never blocks the UI thread.

Academic Compliance

Live

Lesson-plan auditing against the Cambridge planning standard

Live at sais-lessons.web.app. Teachers upload a weekly lesson plan as .pdf or .docx; it is audited against Cambridge lesson-planning standards across ten subject departments, with a general pedagogical rubric as fallback for subjects outside them, then banded and routed to the right head of department.

Cited syllabus codes are checked against the class's actual stage — an out-of-stage citation caps the score — and a deterministic guard catches an unfilled template before it ever reaches the model, because paying for an AI call to discover a blank document is waste. A three-band compliance gate clears at 76% and keeps the two bands below it distinct, because 64–75% and below-64% say different things to a teacher. Those thresholds live in one constants module that the UI reads, rather than being hardcoded at each call site.

A threshold is never moved to improve the pass rate

It changes only if the rubric is judged wrong on the pedagogy, and the reason and the decider are recorded. The rule is written into the repository's agent instructions, because this system decides whether a teacher's work is accepted.

AGENTS.md · standing rule

An IndexedDB offline queue means an upload survives a dropped connection. Teachers who have not submitted get an automatic WhatsApp reminder, and leadership gets a weekly compliance report.

HecTech AI Report Generator

Live

Report cards generated, reviewed and delivered from inside Google Sheets

A Vault Library + Client Shell architecture. The engine and credentials live in one private library; each of thirty-nine classroom spreadsheets runs a thin shell bridge that routes UI requests to it. IT can revoke a single spreadsheet from the Vault's authorisation registry without touching the others, and credentials are isolated per sheet or campus rather than shared.

Auto-healing triggers defeat the Apps Script six-minute execution ceiling. A long batch yields control before it times out and schedules a background trigger to resume itself, so generating three hundred report cards does not require anyone to babysit it.

Most of the engineering here is hardening against the platform's failure modes: a cache-based circuit breaker on the Gemini API so an outage cannot burn the execution quota, formula-injection sanitising on every user-supplied string, a 30-minute OAuth token TTL with cleanup on sheet open, and retry-with-backoff on Drive PDF conversion, which fails intermittently at volume. Subjects are discovered dynamically from sheet headers rather than hardcoded per campus.

QuantSports Engine

Research

Measuring whether a pricing edge exists, and refusing to guess when it can't

A research engine that measures whether a pricing edge exists on two bookmakers, anchoring their lines against sharp consensus books and backtesting the result against historical price-and-result data. It places no bets and offers no advice — it is instrumentation, not a product.

The free-tier budget is enforced in code, not in discipline

A credit ledger refuses any sweep that would breach a monthly or daily allowance before a request is sent, and a dry-run mode prints the projected cost and remaining budget without spending anything.

src/data/creditLedger.ts

Providers are pluggable with an automatic fallback chain. More usefully, the negative results are written down: one bookmaker returning nothing usable on tier-one football is recorded as a measured finding with an identifier, not quietly routed around and forgotten. A research tool whose failures are invisible is a research tool that will mislead you.

Doxamix Foods

Live

Full-stack e-commerce where the interesting problem is concurrency, not the shopfront

A storefront and admin dashboard running at doxamix-foods.web.app: catalogue, cart, checkout and order tracking for customers; sales analytics, inventory and order management for the owner. The shopfront is the easy half.

The real problem is two customers buying the last bottle at the same moment. A naive read-then-write oversells, and an oversold order in a food business means a refund and a lost customer. Stock is guarded in three independent places, each doing a different job.

Client guard → Firestore transaction → security rules

The cart checks availability so the customer gets fast feedback. A Cloud Function then re-reads every product inside a runTransaction, rejects the whole order if any line is short, and writes all deductions atomically — so the check and the write cannot be split by a competing order. Firestore rules permit stock writes to admins only, so no client can reach the number directly. The client layer is convenience; the transaction is correctness; the rules are the boundary.

functions/src/index.ts · read in source

A rejected order is not silently dropped. It is written back as failed with the reason that caused it — which product, stock available, quantity requested — so the owner can see what happened and tell the customer something true.

Role-based access runs through Firestore security rules rather than UI state: the admin dashboard and the business-sensitive collections behind it are gated server-side, and a customer can read their own orders and nothing else. Twenty-six test files cover the cart, product management and order flows.

3D Ludo Engine

Playable

Real-time 3D multiplayer board game with the rules people actually play by

A WebGL board rendered in Three.js — marble slab, wooden framing, dynamic lighting and an orbital camera with pinch-zoom and rotate gestures that work on a phone. Three modes share a single rules core: local pass-and-play, CPU opponents with distinct strategies, and online multiplayer over WebSockets with six-character room codes served by an Express backend.

The part worth building was the rules. Most digital Ludo implements the international rule set, which is not what anyone here actually plays. This one implements the local variant: a ransom mechanism where captured pawns are held by the captor until redeemed, line kicks that jump across the board on a six, and reverse combo kicks. A Vitest suite covers move validation, captures and win conditions, because rule variants are exactly where an implementation quietly drifts from what players expect.

Method

Agents implement. The constraints are mine.

I build with AI coding agents — Claude Code, Antigravity and Cursor. The interesting part is not that they write code; it is what has to be true around them for the output to be trustworthy.

Every repository states its own rules

Each one carries an AGENTS.md or CLAUDE.md setting out what to read first, what must pass before work is called done, and what must never be re-added without review. The architecture, the boundaries and the acceptance criteria are mine; the typing is delegated.

Guardrails come from incidents

One of those files opens: "most rules below exist because something went wrong once." A rule forbidding a compliance threshold being moved to improve a pass rate. A provisioning script that refuses to run unfiltered, because it would invalidate every password-reset link already sent to staff. The written rule is guidance; the code guard is the backstop.

Planning is version-controlled, not conversational

Structured conductor/ tracks hold product guidelines, tech-stack decisions, style guides and workflow per project, so intent survives between sessions and between tools. Agent skills are pinned by content hash in skills-lock.json — the same supply-chain discipline as a dependency lockfile.

Generated code is assumed wrong until measured

Typecheck, unit tests, Playwright E2E and cargo check are gates an agent must clear before finishing, not chores run afterwards. The retracted Elo figure and the "not externally validated" perft labels on this page exist because that discipline caught them.

How I work

Four things I don't compromise on.

Offline is a requirement, not a feature flag

Every product here assumes the network will fail. Write-behind queues in IndexedDB or SQLite, explicit reconciliation on reconnect, and no silent data loss when a background sync races a user's keystrokes.

The client check is never the security boundary

Term locks live in Firestore rules as well as in the UI. Roles resolve server-side, never from browser storage. An IPC SQL bridge allow-lists what is permitted to cross it.

Verified at real scale, not demo scale

The scheduler's release gate is a real school export — fourteen classes, thirty-nine teachers. It is held out of version control because it holds real staff data, which means CI cannot run it, and that limitation is written down rather than glossed over.

Claims get retracted when they don't hold

I audit my own codebases in writing — including one audit that found plain-text credential storage in a project of mine and ranked it the single most serious finding. I would rather ship a documented unknown than an attractive number.
